# Project Documentation

This folder records the verified foundation, product scope, technical proposal, visual system, data model, game rules, animation approach, Android build requirements, test strategy, decisions, and step status.

## Documents

- `MASTER_SPEC_REFERENCE.md`: source-of-truth location and product concepts.
- `FOUNDATION_AUDIT.md`: initial repository audit and observed constraints.
- `PRODUCT_SCOPE.md`: what belongs in the local Android demo and what is excluded.
- `TECHNICAL_ARCHITECTURE.md`: proposed module boundaries and persistence design.
- `FILE_STRUCTURE.md`: current repository tree versus future app structure.
- `DESIGN_SYSTEM.md`: Cosmic Horizon colors, typography, components, and layout direction.
- `ASSET_MANIFEST.md`: supplied and needed assets, including known paths and blockers.
- `DATA_MODEL.md`: proposed local data entities and relationships.
- `GAME_RULES.md`: source-backed quest, XP, attribute, rank, streak, and correction rules.
- `ANIMATION_SPEC.md`: welcome experience and progression motion.
- `ANDROID_BUILD.md`: environment prerequisites and future commands.
- `TEST_PLAN.md`: acceptance tests and when they can run.
- `DECISIONS.md`: unresolved questions and explicit demo-only assumptions.
- `BUILD_STATUS.md`: current stage, evidence, and next authorized action.

The root `AGENTS.md` contains permanent project rules. Follow `ASCENDIA_DEMO_BUILD_STEPS.md` in order. Documentation can describe a plan without implying that a feature exists.
